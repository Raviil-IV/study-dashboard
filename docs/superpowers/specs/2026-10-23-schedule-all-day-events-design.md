# События на весь день и спокойные кнопки в расписании

## Задача

В разделе «Расписание» три изменения:

1. Кнопки «Добавить событие» и «Удалить импорт» слишком яркие — нужны менее насыщенные оттенки той же гаммы.
2. Текст «Добавить занятие» не подходит: в расписание добавляют не только пары.
3. Нельзя создать событие без конкретного времени — конференцию, поездку, день практики.

## Границы

Входит:

- приглушённые варианты кнопок только на странице «Расписание»;
- переименование «занятие → событие» в пределах раздела «Расписание»;
- флаг `allDay` в данных, форме и отображении;
- отображение «Весь день» во всех видах расписания и на дашборде.

Не входит:

- импорт и автосинк РАНХиГС (импортированные занятия всегда с временем);
- дедлайны и задачи;
- события, занимающие несколько дат;
- переименование в других разделах приложения (дашборд, дедлайны).

## Модель данных

В таблицу `lessons` добавляется колонка:

```sql
ALTER TABLE lessons ADD COLUMN all_day boolean NOT NULL DEFAULT false;
```

- `Lesson.allDay?: boolean` на фронтенде.
- `lessonSchema` получает `allDay: z.boolean().optional()`.
- Время у события «на весь день» хранится заглушкой `00:00–23:59`: колонки остаются `not null`, а существующая проверка «конец позже начала» продолжает проходить.
- Импортированные занятия получают `all_day = false` из дефолта БД — их код не меняется.

## Форма

- Под выбором типа появляется чекбокс «Весь день».
- Когда он включён: поля «Начало» и «Конец» скрыты, значения принудительно `00:00` и `23:59`, проверка порядка времени пропускается.
- При выключении возвращаются значения времени, которые были до включения; если их не было (новое событие) — `09:00` и `10:30`.

Тексты раздела «Расписание»:

| Было | Стало |
| --- | --- |
| Добавить занятие | Добавить событие |
| Новое занятие | Новое событие |
| Редактировать занятие | Редактировать событие |
| Удалить занятие? | Удалить событие? |
| Тип занятия | Тип события |
| Следующее занятие: … | Следующее событие: … |
| Занятий пока нет | Событий пока нет |
| Занятий нет | Событий нет |

Сообщения валидации формы: «Введите название события».

## Кнопки

В `Button` добавляются два варианта, существующие не меняются:

- `subtle`: `bg-indigo-100 text-indigo-700 hover:bg-indigo-200`, тёмная тема `dark:bg-indigo-900/40 dark:text-indigo-300 dark:hover:bg-indigo-900/60`;
- `subtleDanger`: `bg-red-50 text-red-700 hover:bg-red-100`, тёмная тема `dark:bg-red-900/30 dark:text-red-300 dark:hover:bg-red-900/50`.

Их получают только «Добавить событие» и «Удалить импорт».

## Отображение

Новый хелпер `lessonTimeLabel(lesson)` возвращает `«Весь день»` при `allDay` и `«ЧЧ:ММ – ЧЧ:ММ»` иначе.

- Карточка в дневном виде — «Весь день» вместо времени.
- Строка «Расписание на сегодня» на дашборде — «весь день» вместо времени начала.
- Чип в «Неделе» — «Весь день» вместо интервала.
- Чип в «Месяце» — время не показывается вовсе (остаётся только название): при 10px «Весь день» не помещается.
- Подзаголовок страницы — «Следующее событие: Конференция · весь день».
- `isLessonNow` для события «на весь день» возвращает `true` в течение всего дня, поэтому бейдж «сейчас» остаётся на нём весь день.
- `nextLesson` для события «на весь день» не переносит его на следующую неделю, если оно сегодня: оно остаётся ближайшим до конца дня.

## Последствия

- Старые записи получают `all_day = false` из дефолта миграции, поведение не меняется.
- Заглушка `00:00–23:59` видна только в БД и API; интерфейс всегда показывает «Весь день». Если у события снять флаг, форма вернёт время, которое было до включения, или стандартные `09:00–10:30`.
- Событие «на весь день» нельзя растянуть на несколько дней: это отдельная задача.
