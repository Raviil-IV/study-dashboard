# Design Spec: Расписание — типы занятий (регулярное / разовое) и кнопки на неделе

Дата: 2026-08-07
Проект: Study Dashboard (React 19 + Vite 7 + TS + Zustand + Tailwind v4)

## 1. Цель

Доработать расписание:

1. На вкладке «Неделя» у карточек занятий появляются кнопки взаимодействия (редактировать / удалить) — сейчас их нет, удалить/изменить занятие можно только из дневного вида.
2. При добавлении занятия пользователь выбирает тип:
   - **Регулярное** — повторяется каждую неделю в один и тот же день и время (текущее поведение);
   - **Разовое** — привязано к конкретной дате, живёт до конца календарной недели (пн–вс) и удаляется автоматически в следующий понедельник.

## 2. Модель данных

`Lesson` (в `src/types/index.ts`) дополняется обязательным полем `type` и опциональным `date`:

```ts
export interface Lesson {
  id: string
  type: 'weekly' | 'once'
  title: string
  weekday: number // weekly: день недели (0=вс…6=сб); once: день недели даты (вычисляется)
  startTime: string // HH:MM
  endTime: string // HH:MM
  date?: string // ISO YYYY-MM-DD, только для type: 'once'
  location?: string
  note?: string
  color?: string
}
```

Семантика:

- `type: 'weekly'` — регулярное; `date` отсутствует; `weekday` задаёт день недели.
- `type: 'once'` — разовое; `date` обязательна; `weekday` = день недели даты, вычисляется при сохранении (чтобы вьюхи фильтровали единообразно).

### Миграция существующих данных

При гидрации из localStorage (persist `getItem`) записи без поля `type` получают `type: 'weekly'`. Старые данные — все регулярные, поведение не меняется. Демо-данные (`src/lib/demoData.ts`) получают `type: 'weekly'` у всех занятий.

## 3. Форма добавления/редактирования (`LessonForm`)

- Вверху формы переключатель (radio): **«Регулярное (каждую неделю)» / «На конкретную дату»**.
- Регулярное: select «День недели» (как сейчас).
- Разовое: поле «Дата» (`input type="date"`), `min` = сегодня (нельзя создать прошедшее разовое). Поле «День недели» скрыто — вычисляется из даты.
- Валидация: заголовок обязателен; `endTime > startTime`; для разового дата обязательна — иначе ошибка «Выберите дату».
- Переключение типа доступно и при редактировании: при смене на «разовое» пользователь выбирает дату, `weekday` пересчитывается из неё при сохранении; при смене на «регулярное» `date` сбрасывается, `weekday` остаётся.

`LessonFormValues` расширяется полями `type` и `date` (`date: string | undefined`).

## 4. Вьюхи

### Дневной вид (`DayView`)

Фильтр занятий на день:

- регулярные: `type === 'weekly' && weekday === день`;
- разовые: `type === 'once' && date === ISO(дата)`.

Сейчас фильтр только по `weekday` — разовое занятие показывалось бы каждый такой день недели; это исправляется.

### Недельный вид (`WeekView`)

Для каждого календарного дня недели (пн–вс):

- регулярные по `weekday`;
- разовые, чья `date` совпадает с этим календарным днём.

Компонент получает пропсы `onEdit` и `onDelete` (как у `DayView`); на карточке занятия появляются кнопки `IconButton` (`edit` / `trash`) в стиле `LessonCard` из дневного вида. `SchedulePage` передаёт те же обработчики, что и `DayView`.

### `nextLesson` и «сейчас»-маркер (`src/lib/date.ts`)

- «Сейчас»: занятие в текущий момент, если время в диапазоне и (`weekly` и сегодня его день) или (`once` и `date` = сегодня).
- `nextLesson`: ближайшее будущее занятие — регулярное в текущий/следующий день недели, разовое с `date >= today` (прошедшие разовые не попадают).
- Функции принимают ту же сигнатуру (`nextLesson(lessons)`), работа с `date` внутри.

## 5. Автоочистка разовых занятий

При чтении состояния из localStorage (persist `getItem`) разовые занятия с `date < понедельника текущей недели` отфильтровываются — «просроченные» не попадают в стор. Регулярные не затрагиваются.

Понедельник текущей недели вычисляется как в `WeekView`: `monday = today - ((today.getDay() + 6) % 7)`, сравнение по ISO-строкам (`toISODate`).

## 6. Обработка ошибок / крайние случаи

- Создание разового занятия на прошедшую дату блокируется (`min` = сегодня + валидация).
- Разовое занятие, прошедшее в течение текущей недели, остаётся видимым (в его день недели) до конца недели.
- Редактирование разового в регулярное и обратно — без потери остальных полей (время, место, цвет, заметка).

## 7. Тесты

- `LessonForm`: переключение типов; разовое без даты → ошибка; валидная отправка обоих типов.
- `DayView`: разовое показывается только в свою дату.
- `WeekView`: разовые попадают в правильный календарный день; кнопки редактирования/удаления вызывают обработчики.
- Стор: миграция (запись без `type` гидратируется как `weekly`); автоочистка (разовое с датой в прошлой неделе не попадает в стор).
- `nextLesson` / `isLessonNow` с разовыми занятиями.

## 8. Файлы под правкой

- `src/lib/date.ts` — `nextLesson`, `isLessonNow` (+ вспомогательное при необходимости)
- `src/lib/demoData.ts` — `type: 'weekly'` у демо-занятий
- `src/store/useStore.ts` — миграция и автоочистка при чтении
- `src/components/schedule/LessonForm.tsx` — переключатель типа, поле даты, валидация
- `src/components/schedule/DayView.tsx` — фильтр с учётом `date`
- `src/components/schedule/WeekView.tsx` — фильтр + кнопки `onEdit`/`onDelete`
- `src/pages/SchedulePage.tsx` — прокинуть обработчики в `WeekView`
- Тесты: `src/pages/SchedulePage.test.tsx`, `src/components/schedule/*.test.tsx` (если есть), `src/lib/date.test.ts`, `src/store/useStore.test.ts`

## 9. Критерии приёмки

1. На вкладке «Неделя» каждое занятие имеет кнопки редактирования и удаления; они работают как в дневном виде (удаление с confirm).
2. При добавлении занятия можно выбрать «Регулярное» или «На конкретную дату»; разовое без даты не сохраняется.
3. Разовое занятие показывается только в свою дату (и на дне, и на неделе), в остальные дни недели не дублируется.
4. После понедельника, следующего за датой разового занятия, оно исчезает из расписания (после перезагрузки страницы).
5. Регулярные занятия не меняют поведение; старые данные из localStorage продолжают работать.
