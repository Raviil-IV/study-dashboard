# Design Spec: Заметки с поддержкой Markdown

Дата: 2026-08-10
Проект: Study Dashboard (React 19 + Vite 7 + TS strict + Zustand v5 + Tailwind v4 + Vitest)

## 1. Цель

Добавить поддержку **Markdown** в заметках: конспекты и идеи можно писать с форматированием (заголовки, списки, таблицы, цитаты) и **блоками кода с подсветкой синтаксиса**. Бэкенд и схема БД не меняются: `Note.content` остаётся обычной строкой, markdown — это формат её отображения.

## 2. Зависимости (новые, только фронтенд)

| Пакет | Зачем |
|---|---|
| `react-markdown` | рендер markdown в React |
| `remark-gfm` | GitHub-расширения: таблицы, чекбоксы `- [ ]`, зачёркивание |
| `rehype-highlight` | подсветка синтаксиса в блоках кода |

- Подсветка — **только по явной разметке языка** (```ts, ```python, ```sql и т.п.), без автоопределения.
- Сырой HTML из контента заметки **не** вставляется в DOM: `react-markdown` экранирует его по умолчанию (XSS-безопасность).
- Стили тем подсветки — собственные `.hljs-*` правила в `src/index.css` (CSS-переменные, светлая и `dark:` тёмная тема); CSS темы `highlight.js` не импортируются.

## 3. Архитектура

Следует паттернам проекта: утилиты в `src/lib/`, UI-компоненты в `src/components/ui/`, компоненты домена в `src/components/<domain>/`, страницы в `src/pages/`.

### Файлы

- `src/lib/markdown.ts` — единый конфиг рендера: `react-markdown` + `remark-gfm` + `rehype-highlight`.
- `src/components/ui/MarkdownView.tsx` — компонент-рендерер на основе конфига из `markdown.ts`.
- `src/components/notes/NoteForm.tsx` — **живой предпросмотр**: textarea слева, `<MarkdownView>` справа; на мобильных (`< md`) — табы «Написать / Предпросмотр».
- `src/components/notes/NoteView.tsx` — **новый** просмотр заметки (модалка) с рендером `<MarkdownView>`.
- `src/components/notes/NoteCard.tsx` — превью остаётся обычным текстом (`line-clamp-4`, без изменений), добавляется клик по карточке → открытие `NoteView`.
- `src/pages/NotesPage.tsx` — состояние модалки просмотра, передача «Редактировать» из просмотра в форму.
- `src/index.css` — стили `prose`-подобного рендера + две темы `highlight.js` (светлая и `dark:`).

## 4. Интерфейс

- **Редактирование:** модалка расширяется до `max-w-4xl` (сейчас `max-w-lg`). Заголовок/предмет/теги — как сейчас, сверху. Ниже — две панели: textarea и живой предпросмотр, синхронизированные с одним состоянием формы (без потери данных при переключении).
- **Мобильный (`< md`):** табы «Написать» / «Предпросмотр» вместо двух панелей.
- **Просмотр:** клик по карточке открывает модалку `max-w-3xl` с отрендеренным markdown; длинный контент скроллится. Кнопки: «Редактировать» (закрывает просмотр и открывает форму с той же заметкой) и «Закрыть».
- **Тёмная тема:** поддерживается — `.hljs` светлая и `dark:` тёмная тема подсветки; оформление рендера через существующие Tailwind-классы `dark:`.

## 5. Данные

- Тип `Note` в `src/types/index.ts` — без изменений.
- Схема БД, миграции, `/api/state`, экшены стора — без изменений.
- Старые заметки с простым текстом корректно рендерятся (обычные параграфы).
- Валидация формы — как сейчас: обязателен только заголовок.

## 6. Ошибки и edge cases

- Пустой контент — рендерится как пустой блок (в просмотре показывается плейсхолдер «—», как в карточке сейчас).
- Неизвестный язык блока кода — показывается без подсветки, но с корректным оформлением блока.
- Сырой HTML в контенте — экранируется, не выполняется (XSS-безопасность).
- Очень длинные заметки — скролл в модалках просмотра/редактирования.
- Переносы строк в markdown (`remark-gfm`) — поддерживаются.

## 7. Тестирование

- `src/components/ui/MarkdownView.test.tsx` (новый):
  - рендер заголовков, списков, таблиц;
  - блок кода с ```ts получает подсветку (проверка классов `hljs` / `language-*`);
  - сырой HTML из контента не попадает в DOM.
- `src/pages/NotesPage.test.tsx` (расширение):
  - клик по карточке открывает просмотр с отрендеренным содержимым;
  - «Редактировать» из просмотра открывает форму с той же заметкой;
  - поиск и создание заметок с markdown-контентом продолжают работать.
- Форма: живой предпросмотр показывает ввод в реальном времени; на мобильной вёрстке доступен переключатель «Написать / Предпросмотр».
- Логика markdown-рендера — библиотечная, свои unit-тесты не пишем, тестируем интеграцию через компоненты.

## 8. Ограничения

- Новые зависимости — только четыре пакета выше (без UI-библиотек и без KaTeX).
- Без изменений бэкенда и схемы БД.
- Без fullscreen-роута: просмотр — модалка поверх текущей страницы.
- TypeScript strict: `noUnusedLocals`/`noUnusedParameters` — неиспользуемые импорты ломают сборку.
