# Study Dashboard

Приложение для организации учёбы: расписание, задачи, дедлайны, заметки и таймер Pomodoro — всё в одном месте. У каждого пользователя свой аккаунт, данные хранятся в PostgreSQL, так что с любого устройства картина одинаковая.

## Возможности

- **Дашборд** — что происходит сегодня: задачи на сегодня, дедлайны на ближайшие 7 дней, занятия на сегодня и быстрый старт фокус-сессии.
- **Расписание** — регулярные занятия (по дням недели) и разовые, с временем, местом, цветом и заметкой. Есть недельный и месячный вид, а занятие редактируется прямо кликом в сетке.
- **Задачи** — приоритет, статус, предмет и дата; на дашборде видно, что на сегодня и что уже просрочено.
- **Дедлайны** — экзамены, контрольные, проекты, домашки и «другое» с датой и временем.
- **Заметки** — Markdown-разметка, теги, закрепление важного сверху.
- **Фокус** — Pomodoro-таймер с настраиваемой длительностью работы и перерывов; завершённые сессии сохраняются в истории.
- **Игры** — «Найди пару», «Змейка» и «Сапёр» с рекордами по уровням сложности (рекорды хранятся на сервере).
- **Настройки** — тема (светлая / тёмная / системная) и длительности помодоро.
- **Админ-панель** — для администрирования и просмотра активности пользователей.

## Стек

- **Фронтенд:** React 19, TypeScript, Vite 7, React Router, Tailwind CSS 4, Zustand; тесты — Vitest + Testing Library.
- **Бэкенд:** Node.js, Express, Drizzle ORM + PostgreSQL; валидация — Zod, авторизация — JWT в httpOnly-cookie, логирование — pino.
- **Прод:** Docker Compose; nginx раздаёт статику и проксирует `/api` на бэкенд.

## Запуск для разработки

Нужны Node.js (20+; в Docker-образе — 22) и для бэкенда — запущенный PostgreSQL.

**Фронтенд:**

```bash
npm install
npm run dev
```

Открой http://localhost:5173.

**Бэкенд:**

```bash
cd backend
npm install
npm run dev
```

По умолчанию сервер слушает порт 3000 и подключается к `postgres://postgres:postgres@localhost:5432/study_dashboard` (адрес меняется через `DATABASE_URL`, порт — через `PORT`). База должна существовать, например: `createdb study_dashboard`. Миграции применяются автоматически при каждом старте, вручную ничего запускать не нужно.

## Продакшен: Docker Compose

```bash
cp .env.example .env    # обязательно задай POSTGRES_PASSWORD и JWT_SECRET
docker compose up -d --build
```

Поднимутся три сервиса: PostgreSQL, бэкенд и фронтенд (nginx). Сайт будет доступен на порту 80 — поменять его можно в `.env` через `FRONTEND_PORT`. Бэкенд наружу не публикуется: статику отдаёт nginx, а запросы к `/api` проксирует на бэкенд внутри сети compose. Миграции БД применяются автоматически.

## Тесты

```bash
npm test                 # фронтенд

```

## Админ-панель

Страница `/admin` и `/api/admin/*` доступны только с ролью `admin`. Роль назначает другой админ через админку, а первому администратору её прописывают вручную в БД:

```bash
psql "$DATABASE_URL" -c "UPDATE users SET role = 'admin' WHERE login = 'твой_логин';"
```

Что умеет админ-панель:

- общая сводка: пользователи (всего, за 7 и 30 дней), активные за неделю, фокус-минуты, доля выполненных задач, просроченные дедлайны и т.д.;
- активность за последние 7 дней — заходы на сайт и выполненные задачи, как общая, так и по каждому пользователю;
- смена ролей и удаление пользователей (удаление каскадно стирает все данные пользователя).

Себя администратор удалить не может и снять себе роль тоже. Активность считается по визитам: запись появляется при открытии приложения и при входе/регистрации; визиты хранятся 7 дней и чистятся автоматически каждые 12 часов, для того чтобы не засорять бд, поэтому график показывает последнюю неделю.
